> 更新时间：2026-08-31
>
> 当前开发分支：`feat/batch-download-center`

- 单图集解析与下载

```text

```

## 2.2 作者主页批量扫描

已经支持作者主页批量读取作品。

支持模式：

```text
post  作者发布作品
like  作者点赞作品
mix   合集作品
```

### 发布作品

输入：

```text
https://www.douyin.com/user/<sec_uid>
```

能力：

- 分页读取作者作品
- 最多扫描 1～500 条
- SQLite 去重
- 增量模式
- `aweme_id` 精确去重
- `author_sec_uid + create_time` 快速停止旧内容分页
- API 首屏失败时可选 Playwright 浏览器兜底

### 点赞作品

作者主页选择“点赞作品”模式。

能力：

- 使用 `GetUserLike()` 分页读取
- SQLite `aweme_id` 去重
- 支持数量限制

注意：

- 目标用户必须允许查看点赞列表
- Cookie 需要具备对应访问权限
- 点赞内容不能使用作品 `create_time` 作为点赞时间进行增量截断，因此主要依赖 `aweme_id` 去重

### 合集作品

支持：

```text
https://www.douyin.com/collection/<mix_id>
https://www.douyin.com/mix/<mix_id>
```

能力：

- 自动识别合集链接
- 获取合集信息
- 分页读取合集作品
- SQLite 去重
- 批量选择与下载

## 2.3 SQLite 去重与增量

已经把 SQLite 从简单历史记录扩展为内容发现和任务持久化的一部分。

核心能力：

- `aweme_id` 判断作品是否已经发现
- 按作者读取最新作品发布时间
- 存储作者、标题、类型、发布时间、原始 metadata、任务 ID
- 查询最近作品
- 查询历史任务
- 服务重启后仍然可以读取历史任务

发布作品增量逻辑：

```text
author_sec_uid
+
create_time
+
aweme_id
```

点赞 / 合集主要使用：

```text
aweme_id
```

## 2.4 异步任务系统

已经实现作者主页 / 合集扫描任务。

任务状态：

```text
queued
  ↓
running
  ↓
completed / failed
```

服务重启时，如果数据库中的历史任务仍处于：

```text
queued / running
```

Web 端会显示为：

```text
interrupted
```

避免用户误以为任务仍在后台运行。

任务会持久化：

- URL
- mode
- max_items
- incremental
- 作者信息
- 总数
- 成功数
- 跳过数
- 失败数
- 错误信息
- 创建 / 开始 / 完成时间

主要接口：

```text
POST /api/v1/jobs
GET  /api/v1/jobs
GET  /api/v1/jobs/{id}
POST /api/v1/jobs/{id}/retry
```

## 2.5 真正的批量下载

已经从“批量扫描后逐个点击下载”升级成真正的批量下载。

Web 支持：

- 全选
- 取消全选
- 任意多选
- 下载选中作品

为了避免 300～500 个 `aweme_id` 放进 GET URL 后超过浏览器 / Nginx 请求行长度，使用一次性下载票据。

流程：

```text
POST /api/v1/batch/prepare
        ↓
创建一次性 ticket
        ↓
GET /api/v1/batch/stream?ticket=...
        ↓
服务端流式 ZIP
```

Ticket：

- 一次性
- 10 分钟有效
- 避免长 URL

ZIP 行为：

### 视频

```text
001_标题_aweme_id.mp4
002_标题_aweme_id.mp4
```

### 图集

```text
003_图集标题_aweme_id/
├── 001.jpeg
├── 002.jpeg
└── 003.jpeg
```

### 单项失败

```text
errors/<aweme_id>.txt
```

单个作品失败不会中断整个 ZIP。

响应增加：

```text
X-Accel-Buffering: no
```

减少 Nginx 对长时间 ZIP 流进行缓冲。

核心设计仍然保持：

> 媒体边获取边写入客户端响应，不长期保存视频到服务器。

# 3. 当前能力边界

虽然现在已经具备完整 Web 工作台骨架，但仍有一些明确的能力边界。

## 3.1 批量下载仍是流式 ZIP

优点：

- 不长期占用服务器磁盘
- 用户点击后即可开始返回内容
- 部署简单

限制：

- 浏览器无法像专业下载器一样显示每个 ZIP 内作品的独立实时下载进度
- ZIP 流中途断线后无法直接断点续传整个任务
- 超大规模媒体任务会占用一个长期 HTTP 连接

未来可以保留流式 ZIP，同时增加真正的后台下载任务模式作为可选能力。

## 3.2 浏览器兜底范围有限

当前主要验证：

```text
post
```

尚未完整覆盖：

```text
like
mix
collect
collectmix
```

## 3.3 任务队列还可以继续加强

目前已经有异步任务和任务中心，但后续仍可增加：

- 固定 worker 数量
- 最大并发任务限制
- 排队优先级
- 任务取消
- 任务暂停 / 恢复
- Job TTL 清理
- 下载并发控制

## 3.4 Android 客户端尚未同步全部 Web 新能力

当前主要新增功能集中在 Web。

后续需要逐步同步：

- 批量扫描
- 批量选择
- 任务中心
- 作品库
- Cookie 状态
- 账号中心

# 8. 第五阶段：直播能力

## 8.1 P2 / P3：直播录制

支持：

```text
live.douyin.com/<room_id>
```

可能包括：

- FLV
- HLS
- 开播状态
- 下播自动结束
- 录制时长
- 文件大小
- 录制任务中心

但直播录制与现有“不长期落盘”架构存在明显差异。

它天然需要：

- 长时间任务
- GB 级磁盘空间
- 文件生命周期
- 断线重连
- FFmpeg
- HLS 后处理
- 磁盘配额
- 文件清理策略

因此目前建议暂缓，等下载任务、队列、存储策略成熟后再做。

# 12. 推荐产品形态

如果继续按这条路线发展，项目未来已经不再只是一个简单的“抖音下载器”。

推荐最终产品结构：

```text
Douyin Content Manager
│
├── 下载
│   ├── 链接下载
│   └── 批量下载
│
├── 内容
│   ├── 作品库
│   ├── 作品详情
│   ├── 评论
│   └── 文稿
│
├── 账号
│   ├── 关注
│   ├── 收藏
│   ├── 收藏合集
│   └── 喜欢
│
├── 发现
│   ├── 搜索
│   └── 热榜
│
├── 自动化
│   ├── 作者订阅
│   ├── 自动同步
│   └── 通知
│
├── 任务
│   ├── 扫描任务
│   ├── 下载任务
│   └── 录制任务
│
└── AI
    ├── 转写
    ├── 总结
    └── 评论分析
```

推荐开发策略：

> 先把“下载器”做稳，再扩展“账号内容管理”，随后增加“发现 + 自动化”，最后再做 AI 和直播等重型能力。

这样可以避免功能很多但核心链路不稳定，同时也能让每个版本都具备清晰、可交付的产品价值。
